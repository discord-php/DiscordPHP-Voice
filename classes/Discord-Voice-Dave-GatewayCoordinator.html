GatewayCoordinator.php : 31

Handles all DAVE E2EE gateway protocol logic on behalf of the voice WebSocket.

This class owns every DAVE opcode handler and helper that was previously embedded in WS. WS keeps thin proxy methods so the opcode dispatch table remains unchanged; all real work happens here.

handleDaveMlsKeyPackage()

GatewayCoordinator.php : 177

Handle an inbound opcode 26 (VOICE_DAVE_MLS_KEY_PACKAGE) frame from the gateway.

public handleDaveMlsKeyPackage(mixed $data) : void

Opcode 26 is primarily client→server: we send our own key package to the gateway via sendDaveKeyPackage() during the DAVE epoch-1 setup. The gateway may also forward a remote member's key package back to us as an informational notice — that is what this handler receives.

The gateway (server) is responsible for aggregating all key packages and driving the subsequent proposal/commit flow. We passively receive the forwarded package; no action is required on the client side.

Per the Discord DAVE spec: "Key packages are only used one time" — each time we need to join or rejoin a session we generate and send a fresh key package.
